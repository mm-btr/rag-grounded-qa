# Калибровка судей

Сверка вердиктов LLM-судей на одном прогоне: агент проходит все ответы и выносит свой вердикт по каждому.

## Вход

- `../samples/<run>-samples.jsonl` — полные тексты (вопрос/ответ/эталон), вердикты и комменты судей.
- Контракты судей `eval/judges/*.md` — та редакция, которой судился прогон.

## Правила процедуры

- Проходятся **все** строки прогона, не выборка.
- **Слепая сверка**: сначала свой вердикт, только потом смотреть вердикт судьи — иначе якорение.
- Вердикт выносится **по контракту судьи**, не по здравому смыслу. Расхождение контракта со здравым смыслом — отдельный класс «спорное», не правка вердикта на лету.
- Арифметика производных величин (разницы, доли, проценты, кратности) пересчитывается вручную.
- Сверка по обеим сторонам: PASS судьи → ловим ложные зачёты, FAIL судьи → ложные незачёты.

## Формат журнала

Журнал `calibration-<run>.md` в этой папке — только факты сверки; правки судей/эталонов из находок — отдельным обсуждением, в журнал не пишутся.

# Калибровка судей — <run>

Прогон <run> · судья <модель> · калибровщик <модель> · пройдено N/N · расхождений K:
PASS-сторона — X ложных зачётов · FAIL-сторона — Y ложных незачётов + Z спорных.

## Итог
- PASS-сторона: ложных зачётов сколько, что именно проверено.
- FAIL-сторона: сколько ложных + сколько спорных; в какую сторону ошибается
  судья и что это значит для заявленных цифр.

## Расхождения (мой вердикт ≠ судья)
Таблица: № | Тип | Судья | Мой | Почему. У спорных в «Почему» — «если зачесть:
было → стало». Под таблицей — влияние на заголовки отчёта.

## Классы поведения судьи
Подзаголовок на каждый системный класс: счёт случаев за/против, цитаты
противоречащих комментов судьи, первопричина и адресат лечения —
судья / системник / эталон.
